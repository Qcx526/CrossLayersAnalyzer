### 6. ★ 间接跳转解析（本轮最重要的技术改进）
**问题**：旧实现遇 `jalr` 只连 fall-through(+4)，间接跳转目标块被判"不可达"
→ **假阴性**。安全工具的假阴性意味着"我说安全，其实不安全"。

发现并修复**三个真实 bug**（用 capstone 直接验证 operand 结构定位）：

| # | 位置 | Bug | 后果 |
|---|---|---|---|
| 1 | `lifter._parse_operands` JUMP 分支 | 用"索引 0 且是 JUMP/CALL 就当作链接寄存器"一刀切；`jr t0` 只有 1 个寄存器操作数，t0 被吃成目标 | `sources` 为空，间接跳转目标寄存器彻底丢失 |
| 2 | `lifter._parse_operands` MEM 分支 | 只对 `T_IMM` 记 `immediate`，`lw t0, 24(a1)` 的位移 24 丢失 | 跳转表地址算不出来 |
| 3 | `cfg._collect_indirect_targets` | 用 `e.startswith("reg:")` 判寄存器，但 `sources` 是 `Expr` 对象；且没递归展开 `add(base, const)` 嵌套 | 基址寄存器取不到 |

修复方式：
- 判据改为"**存在第二个寄存器操作数时**第一个才是链接寄存器"
- MEM 位移写入 `immediate`
- 新增 `_regs_in()` / `_consts_in()` **递归**收集表达式树里的寄存器与常量

新增 CFG 三策略（保守过近似，宁可多连边也不漏边）：
1. 跳转表识别：`lw t0, off(base)` + `lui base, hi` → 枚举表项地址
2. 已知函数入口
3. 孤岛入口兜底（含"终止指令之后"的地址）

新增统计指标并写入报告「3b. 控制流可信度」：
`indirect_jumps` / `indirect_resolved` / `indirect_unresolved` / `cfg_confidence`。
**这是设计纪律的体现**：解析不出来的部分不能被静默渲染成"不可达"。

### 四问的答案要点（避免下次再查）
1. **工具**：纯 Python + z3 / capstone / pyelftools / networkx / jsonschema /
   PyYAML。**刻意不用** WSL（安全策略拦截）、KLEE、Ghidra、商业 EDA ——
   这是为论文复现性做的取舍，不是妥协。
2. **输入**：ELF（自动识别 magic）或裸 .bin（**必须给 base_address**）
   + `TriggerContract`（`contracts/` 里的代码，非配置）
   + `AnalysisConfig`（`input_regs` 是最关键参数，定义"攻击者从哪进来"）。
   **输出**：`AnalysisRun`；7 类逐块判定；`out/evidence.db`(CLEG, 36 节点/30 边)；
   `out/reports/*.md`(13 份)；`out/summary.json`；`out/samples/*.bin`(13)。
3. **样本**：**不是找来的，全部自研合成**，13 个，由 `tests/fixtures.py`
   的手写 RISC-V 编码器现场生成；**不用汇编器**，因为那样地面真值会依赖
   "编译器按我预期编码"这个不可验证的假设。编码器由 capstone 交叉验证
   （59/59）保证真值可信。真实固件**没有地面真值**，所以用合成样本换
   真值确定性 —— 这是刻意的取舍，写成 Threats to Validity。
4. **用法**：`pip install -r requirements.txt` → `python tests/run_tests.py`
   → 见 README §3 的 `run_analysis()` 用法片段 → 写新契约复制
   `contracts/div_zero.py`，**trigger 只放判别性谓词**。
   读报告顺序：sha256 → 形式化完整性 → cfg_confidence → 判定结果。
   **结论上限是 E1，不能说"在目标设备上成立"。**
